# 退出码 139 / SIGSEGV 段错误解析

## 一、139 是怎么来的

```text
139 = 128 + 11          ← Linux 的约定：128 + 信号编号
信号 11 = SIGSEGV        ← Segmentation Fault（段错误）
```

这不是 `return 0` 的返回值，而是**进程被信号 11 杀死的标记**。CLion 显示的 `interrupted by signal 11: SIGSEGV` 就是这个意思。

## 二、为什么"读"没事、"写"却崩了

这是关键区别：

| 操作 | 结果 |
|------|------|
| `*(addr)` 读 | 栈页本来就是已映射且可读写的，读出来是垃圾，但不会崩——所以你看到了那行负数 |
| `*addr = 11` 写 | 把 11（`0x0000000B`）写进了这块内存，破坏了程序自己还要用的数据 |

被破坏的东西可能是：

- **返回地址 / 保存的 RBP**（栈帧的"回程车票"）
- 编译器保存的 **callee-saved 寄存器**
- 旁边某个**局部变量**（`p`、`size`、`addr`、`arr` 等）

一旦这些数据被覆盖，崩溃就发生在**下一次用到它们的时候**——最常见的就是 `main` 收尾执行 `leave; ret`（恢复栈帧、跳回调用者）的瞬间：CPU 跳到一个被 11 污染过的地址 → 访问非法内存 → **SIGSEGV**。
